2) Backend: runtime / architecture status
============================================================
2.1 Entry points
- backend/src/server.js
  - Starts Express on PORT (default 8080)
  - Logs: Planora backend listening on http://localhost:${port}

- backend/src/app.js
  - Middleware:
    - helmet()
    - express.json({ limit: '1mb' })
    - cors(corsOptions)
    - express-rate-limit (window/max configurable via env)
  - Health endpoint: GET /health => { ok: true }
  - Mounted routers:
    - /api/tasks -> backend/src/routes/tasks.routes.js
    - /api/planner -> backend/src/routes/planner.routes.js
    - /api/chat -> backend/src/routes/chat.routes.js
    - /api/analytics -> backend/src/routes/analytics.routes.js
    - /api/reminders -> backend/src/routes/reminders.routes.js
  - 404 + error handler

2.2 CORS config
- backend/src/config/cors.js
  - origin: process.env.CORS_ORIGIN || 'http://localhost:5173'
  - allowedHeaders: Content-Type, Authorization
  - credentials: false

2.3 Authentication
- backend/src/middleware/auth.js
  - Reads Authorization header: expects "Bearer <token>"
  - Uses Firebase Admin: auth.verifyIdToken(token)
  - Sets req.user = { uid, email }
  - Throws ApiError(401) if token missing

2.4 Error handling
- backend/src/middleware/errorHandler.js
  - notFoundHandler: returns 404 JSON
  - errorHandler:
    - statusCode = ApiError.statusCode or 500
    - logs stack only for statusCode >= 500
    - response: { error: message, details: err.details || null }

2.5 Utilities
- backend/src/utils/asyncHandler.js: standard async wrapper for Express handlers
- backend/src/utils/apiError.js: ApiError class
- backend/src/utils/validation.js:
  - taskSchema (zod) defines payload shape for tasks:
    - title: string 1..200
    - description: string max 2000 (optional)
    - priority: enum High|Medium|Low default Medium
    - category: string 1..50 default Work
    - dueDate: string datetime OR date optional nullable
    - completed: boolean optional default false

3) Backend: implemented endpoints / behavior
============================================================
All routes are protected by requireAuth (router.use(requireAuth)).

3.1 Tasks
- Routes: backend/src/routes/tasks.routes.js
- Endpoints:
  - GET /api/tasks/today
    - Queries Firestore collection "tasks" by userId
    - Orders by dueDate asc
    - Filters tasks whose dueDate matches "today" (supports Timestamp or string/date)
    - Returns: { tasks: [...] }

  - GET /api/tasks
    - Query params: priority, category, status
      - status=completed => where completed == true
      - status=pending => where completed == false
    - Returns: { tasks: filtered[] }

  - POST /api/tasks
    - Validates req.body via taskSchema
    - Creates task doc with:
      - userId, title, description, priority, category
      - completed: Boolean(completed)
      - dueDate: dueDate ? new Date(dueDate) : now
      - createdAt/updatedAt timestamps
    - Returns 201: { id }

  - PATCH /api/tasks/:taskId
    - Checks task exists and belongs to userId
    - Accepts partial payload via taskSchema.partial()
    - Updates provided fields; dueDate -> null if explicitly set to falsy/empty
    - Returns: { ok: true }

  - DELETE /api/tasks/:taskId
    - Checks task exists and belongs to userId
    - Deletes doc
    - Returns: { ok: true }

  - POST /api/tasks/:taskId/toggle
    - Flips completed boolean
    - Updates updatedAt
    - Returns: { ok: true, completed: next }

3.2 Planner (Gemini structured JSON)
- Routes: backend/src/routes/planner.routes.js
- Endpoint:
  - POST /api/planner/generate
    - Body: { goals: string, timezone?: string }
    - Requires goals string non-empty
    - Calls plannerService.generateDailyPlan({ userId, goals, timezone })
    - Returns: { plan: <json> }

- backend/src/services/ai/plannerService.js
  - Calls aiService.generateText with:
    - systemInstruction: strict JSON-only schema (timeline, priorities, focusSuggestions, estimatedProductivity, habitsImprovements, reschedule)
    - prompt includes timezone and seed ideas
  - normalizeJSON extracts the first {...} JSON substring then JSON.parse
  - Validates presence of json.timeline array
  - Stores last plan to Firestore collection "ai_memory" (non-fatal on failure)

3.3 Chat (Gemini text + Firestore persistence)
- Routes: backend/src/routes/chat.routes.js
- Endpoints:
  - GET /api/chat
    - Lists recent conversation summaries (from chats collection)
    - Returns: { conversations: [...] }

  - GET /api/chat/history?chatId=<id>
    - Returns message history: { chatId, history }

  - POST /api/chat/message
    - Body: { message: string, chatId?: string }
    - If chatId provided:
      - loads thread and ensures user ownership
    - Else creates new doc id
    - Loads previous messages (if any) and builds prompt context
    - Calls aiService.generateText (systemInstruction plain actionable)
    - Persists messages array into chats doc (merge)
    - Also stores lightweight record in "ai_memory" (non-fatal)
    - Returns: { chatId: <id>, message: <aiText> }

- backend/src/services/ai/chatService.js includes:
  - summarizeConversation(last 8 turns)
  - listRecentConversations: Firestore "chats" ordered by updatedAt desc limit 10

3.4 Analytics
- Routes: backend/src/routes/analytics.routes.js
- Endpoints:
  - GET /api/analytics/today -> analyticsService.getTodayAnalytics
  - GET /api/analytics/weekly -> analyticsService.getWeeklyAnalytics

- backend/src/services/analytics/analyticsService.js
  - Today analytics:
    - Reads tasks from Firestore by userId (no date index filtering at query level)
    - Builds "todays" by matching dueDate to today; fallback uses updatedAt matching today
    - productivity score = round(completed / total * 100)
    - streak: up to 60 consecutive days where at least one completed task updated within the day
    - focusTimeHours approximated from completed tasks * 25 minutes
    - recentActivity returns top 5 tasks sorted by updatedAt

  - Weekly analytics:
    - last 7 days array built in JS
    - weekly points: productivity per day computed similarly (dueDate match or updatedAt match)
    - avgProductivity = mean of points
    - completionRate uses overall completedTasks / totalTasks
    - overdueRisk heuristic: pending tasks with dueDate before today

3.5 Reminders (scaffolding)

4) Backend: AI integration status
============================================================
- backend/src/services/ai/aiService.js
  - Uses @google/generative-ai
  - require env: GEMINI_API_KEY
  - Model: gemini-1.5-flash
  - generateText({ prompt, systemInstruction }):
    - builds parts = [systemInstruction?, prompt]
    - model.generateContent({ contents: [{ role: 'user', parts }] })
    - returns response.text()

- backend/src/prompts/
  - plannerPrompt.js, chatPrompt.js exist but are not referenced in the services read above (current services inline SYSTEM strings).

- backend/src/firebase/admin.js
  - Initializes Firebase Admin once
  - Env required (if admin.apps.length == 0):
    - FIREBASE_PROJECT_ID
    - FIREBASE_CLIENT_EMAIL
    - FIREBASE_PRIVATE_KEY (supports escaped newlines via replace(/\\n/g,'\n'))
  - Exposes:
    - db = admin.firestore()
    - auth = admin.auth()
