2) What is implemented (current codebase)

2.1 Backend (Node.js/Express)
- Server/app wiring
  - Express app setup with common middleware (helmet, JSON limits, CORS, rate limiting).
  - Health endpoint: GET /health => { ok: true }
  - Centralized 404 + error handling.
- Authentication
  - Firebase ID token verification middleware (Authorization: Bearer <token>).
  - req.user populated with uid + email.
- Core protected APIs (requireAuth)
  1) Tasks
     - GET /api/tasks/today
     - GET /api/tasks (filters: priority, category, status=completed|pending)
     - POST /api/tasks (validates input; creates task)
     - PATCH /api/tasks/:taskId (partial update)
     - DELETE /api/tasks/:taskId
     - POST /api/tasks/:taskId/toggle
  2) Planner (Gemini)
     - POST /api/planner/generate
     - Produces structured JSON plan (timeline + additional fields) via Gemini.
     - Attempts to store last plan in Firestore (non-fatal).
  3) Chat (Gemini + persistence)
     - GET /api/chat (recent conversation summaries)
     - GET /api/chat/history?chatId=<id>
     - POST /api/chat/message
       - Creates/loads chat thread (ownership enforced)
       - Persists messages to Firestore.
  4) Analytics
     - GET /api/analytics/today
     - GET /api/analytics/weekly
     - Computes productivity/completion/streak heuristics in code.
  5) Reminders (present but not complete)
     - GET /api/reminders, POST /api/reminders, DELETE /api/reminders/:reminderId
     - Current controllers return stub responses (empty list / stub id).
